## [BE] POST эндпоинт, отсуствует валидация для поля sellerId

### Приоритет

**High** - система не справляется со своей основной функцией

### Шаги воспроизведения

1. Выполнить POST запрос передав следующий JSON объект

```json
{
  "sellerID": -5151,
  "name": "asd",
  "price": 300,
  "statistics": {
    "likes": 1,
    "viewCount": 1,
    "contacts": 1
  }
}
```

### Фактический результат

- В ответе:

```json
{
  "status": "Сохранили объявление - (id созданного объявления)"
}
```

### Ожидаемый результат

- В ответе:

```json
{
  "result": {
    "message": "sellerID должен быть числом в диапазоне 111111-999999"
  },
  "status": 400
}
```

### Пояснение

Это баг, поскольку идентификатор не может быть отрицательным числом

**High** - система не справляется со своей основной функцией

1. Выполнить POST запрос передав следующий JSON объект

```json
{
  "sellerID": 111111,
  "name": "asd",
```

```json
  "statistics": {
    "likes": -1,
```

Это баг, поскольку likes, viewCount, contacts не могут быть отрицательными числами

## [BE] POST эндпоинт при успешном создании должен возвращать статус 201

### Приоритет

**Medium** - Это ошибка в проектировании API, но система от этого не пострадает

### Шаги воспроизведения

1. Выполнить POST запрос передав следующий JSON объект

```json
{
  "sellerID": 111111,
  "name": "asd",
  "price": 300,
  "statistics": {
    "likes": 1,
    "viewCount": 1,
    "contacts": 1
  }
}
```

### Фактический результат

- В ответе:

```json
{
  "status": "Сохранили объявление - (id созданного объявления)"
}
```

- статус 200

### Ожидаемый результат

- В ответе:

```json
{
  "status": "Сохранили объявление - (id созданного объявления)"
}
```

- статус - 201

### Пояснение

Здесь статус не соответствует стандарту REST арфитектуры
